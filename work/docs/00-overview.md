# IsotopeMD 总纲（探讨稿）

> **一句话**：IsotopeMD 是一个**可执行的渐进形式化黑板**：以自由文本为入口、以渐进形式化图为核心、支持状态传播与可选求值的个人外置思维系统。

**本文档是探讨稿，不是 spec。** 它的任务是：把三份聊天记录（`chat2_grok4.6` / `chat3_glm5.3` / `chat4_claudeopus5_2`，存于 `work/Former_Chat_Refs/`）里推演出来的设计哲学、后端要求、术语、分歧和待定项摊在一个地方，供后续逐个敲定。它**故意不把细节落死**——落死的活由后面的具体文档干（见 §9 文档地图），那样同步成本才可控。

## 1. 这是什么项目

### 1.1 起源与动机

做这个东西的直接 trigger 是打 MCM 时遇到的地狱：策略管理混乱、算法知识性研究方向混乱、人员调度混乱，且三者相互耦合。往外推，同类场景还有：出外勤的人员调度（谁替谁、谁在谁不在）、Aspen / Simulink / Grasshopper 的草稿层、软件多层 UML 拓扑、控制流要结合"人的心情"这类软变量的系统、甚至开发菜谱——**共同点是：过程很乱、状态是活的、过程本身就是结果**。

对标物都不满足：Obsidian 只是 md 编辑器加不支持图语法的渲染图；draw.io 的线是死的；Aspen / Simulink 要求先定义后连线，扼杀草稿性；Grasshopper 是纯 DAG，不允许"我还没想清楚这是什么"的状态存在。

### 1.2 是什么 / 不是什么

**是**：个人/小团队的外置思维系统。一块可以先乱画、后形式化、且形式化之后真的能跑的黑板。

**不是**（早期野心在聊天中被主动收缩过）：

- 不是通用节点式科学计算平台（那是 Yahoo Pipes / Quartz Composer 撞过的墙）；
- 不是 LangGraph 可视化器、不是 Simulink 替代品、不是 Obsidian 插件、不是通用 Agent IDE；
- 不追求节点内的专业性——专业性靠用户自己接 python 脚本、做预制电池，那是生态，是后话。

### 1.3 双对标（拆开的，不是混的）

| 维度 | 对标谁 | 含义 |
|---|---|---|
| **完备性** | Grasshopper / Simulink / Orange / Aspen 草稿层 | 内核动词要齐：有向图、边载荷、复合载荷、成环+时间、手填打断、残缺部分跑、封装复用、插件电池、历史记录。**这些能力必须存在且都能零 GUI 通过 API 做到。** |
| **交互** | 黑板 / draw.io / 便利贴 | 先当一块更好用的纸，再让纸上的箭头偶尔变成真的流。不许用前置仪式（先声明才能画）教育用户。 |
| **刻意不对标** | 工业求解器的严谨性 | 不做收敛执法、单位制执法、形式化验证、必须先定义再连线。严谨是用户自己造电池或手册约束出来的，不是软件锁出来的。 |

## 2. 设计哲学

以下各条互相支撑，是后续所有裁决的第一性依据。每条给出精髓与理由。

### 2.1 渐进形式化（核心差异化）

允许"先随便写，想清楚了再正式化"。**正式性是每个对象的一个状态，不是一种对象类别**【倾向，见待定 O-1】。传统节点工具要求写下任何东西之前就想清楚它的类型，这扼杀草稿性；本项目的根基是允许"我还没想清楚这是什么"作为一等状态存在。这是 Scratch / CubeMX 都缺的那一半。

### 2.2 过程即结果

草稿在活着的过程中被使用、被查阅、被修改，**状态轨迹本身就是产出**。"谁替谁上厕所"的调度状态变化史，不需要"算出"什么，记录下来就是结果。推论：历史快照机制（环形缓冲 + 手动打点）不是附加功能，是产品灵魂的一部分【实现时机待定】。

### 2.3 md 是输入法，不是文件系统

用户想要的"直接打字、不转头点下拉"是**编辑手感**，不是"md 当数据库"。三层职责：内容层用 md（人和 agent 自由写）、语义层用结构化数据（只能走 API）、导出态的 md 是单向只读投影。详见 §3 与 §7（"万物皆 md"已否决）。

### 2.4 默认善良，引导不锁

约束分四层：物理上不能不做的极少（边要有端或明确悬空、文件能存开）；默认行为善良可改（框选变组、穿过框的箭变成口）；手册/文化层不禁止（一张纸画宇宙也允许打开）；可选严谨做成开关（类型检查、单位、步进仿真）。**用操作语法逼人正确建图，终点就是古板求解器：每一步合法，但不敢乱画。**

### 2.5 允许残缺，错了能擦

悬空输入、孤儿对象、断边的图必须能继续部分运行，不整图锁死，不弹报错对话框。悬空不是错误，只是"这一支是 undefined"。用户搞砸时像擦粉笔：撤销、拆盒、字回摊上。

### 2.6 内核完备，客户端人性

两层产品、一层内核。内核是工业能力表上的图机（动词齐全、零像素）；客户端分三种：**人的纸**（黑板手势）、**魔杖**（框选抓取的手势宏）、**Agent/脚本**（直接打命令，跳过一切草稿阶段）。完备性在内核，人性在客户端。

### 2.7 GUI 猜测只活在命令生成的一瞬间

前端可以按几何猜语义（左边优先输入、吸附、对齐），但猜测的结果必须凝固成一条**带明确参数的 Command**；后端只执行命令，绝不读坐标、缩放、DPI。抓取是给人用的创意功能，不是后端概念。解耦是否干净，用"无界面跑通"一票否决（§3.4）。

### 2.8 Agent 是高级用户，不是 root

Agent 与 UI 走同一套 Command API，没有第二套写路径。图结构永远合法这件事由 API 的 schema 校验保证，不由 agent 的自觉保证。agent 改崩了能拦下、能一键撤销、每一步可审计。想参考的先例：Rhino 脚本 API 从不让你直接改 `.3dm`，VSCode 插件改文档必须走 `WorkspaceEdit`。

### 2.9 本体不依赖任何外部框架

Agent 框架（LangGraph 等）、MCP、python 生态，全部只能出现在 adapter / 插件层。核心对象不认识任何具体框架。许可证传染与技术协议传染都要防：借鉴思路自己重写是干净的，把核心模型绑死在别人的生命周期上不是。

### 2.10 先验证领域模型，再决定宿主平台

不为跨平台打包、数据库选型、分发方式提前支付架构成本。库形态先于服务形态（库→服务是薄包装，服务→库是重构）；Web 形态是成品形态不是前身；桌面壳是将来想要真文件系统/子进程时顺手套的一层皮。

## 3. 分层与后端要求

### 3.1 三层分离

```
视图层    md 渲染 / 图渲染 / 表格渲染      ← 只读投影，可多种，含"导出为 md"
语义层    Object / Slot / Edge / Group…    ← 唯一真相源，只能走 Command API 修改
内容层    Block（一块块 md 便利贴）          ← 死文本，人和 agent 自由读写
```

- 死块只有内容层。正式化 = 语义层多出一条可引用、可求值的记录。
- 正式块与原文的关系：**独立副本 + origin 软回链**【已定，AGENTS.md 禁止清单】。不做任何实时跟随锚定（双向同步 / tokenId / 指纹重定位均禁止，见 §7）。
- md 不是存储格式【已定】。把语义结构塞进 frontmatter 或自定义 md 语法 = 走 Obsidian 的死路。

### 3.2 形态：库，不是服务【已定】

graph-core 是 npm 包，同进程函数调用。**禁止**引入 localhost 后端服务器、HTTP/WebSocket 内部通信。"前后端解耦"在这里指**模块边界**（包边界），不是进程边界。将来需要服务化的三个信号：想做 TUI/CLI 同时操作图、agent 要跑在独立进程、想远程访问图——一个都没出现之前，服务化是纯负债。

### 3.3 后端铁律（继承 AGENTS.md + 聊天共识）

1. 所有写操作必须变成 Command：可序列化、有版本号、可撤销（自带逆操作或快照）。
2. UI 和 Agent 共用同一套 Command API，不存在第二套写路径。
3. 求值器、存储、status 传播**禁止读取像素 / DPI / 缩放**。同一套图坐标全改成乱的，求值结果必须不变。
4. 正式化**不重排、不改写**用户的散文本。数据重排（布局）是另一件事（空格键），且空格只触发重新布局，后端整理在 idle 时静默做【已定，禁止清单】。
5. `status`、`lastEval` 等运行时字段由求值器独占，Agent 写它等于伪造计算结果【已定，禁止清单】。
6. 数据格式必须携带 `schema_version`；老文件要能迁移（参照 Blender DNA 思想的最低配：版本号 + 迁移函数）。
7. 平台差异（文件系统 / 存储 / 子进程 / 网络 / 窗口件）只允许出现在 `HostBridge` 实现文件里（`host.browser.ts`，将来的 `host.tauri.ts`）。查询能力（`host.capabilities.has(...)`），不判断环境（禁止 `if (isDesktop)` 散落）。

### 3.4 无头验收标准（一票否决）

没有浏览器、没有任何 rect，必须能建图并跑：

```
createVar T, k
createProcess heat, ports {T, k} → q
connect …
set manual T = 300
tick × N
assert q 有值或 undefined，图不崩
```

Agent 快速起一个流仿真或头脑风暴对话树，走的就是这条路的零像素版本。这条跑不通，架构就是错的。

### 3.5 平台五条缝（HostBridge 要封住的）

| 缝 | 浏览器 | 桌面壳 | 封法 |
|---|---|---|---|
| 文件系统 | 几乎不能 | 完整读写 | `host.fs.*` |
| 存储 | IndexedDB | SQLite/文件 | `ProjectRepository` 接口 |
| 子进程 | 不能（python 电池全废） | 能 | `host.exec()` |
| 网络/密钥 | CORS 限制、key 暴露 | 无限制 | `host.llm()` |
| 窗口件 | 无菜单/全局快捷键/多窗口 | 有 | 需要时再加 |

v1 只需预留接口名 + 浏览器降级实现，不实现桌面版。

## 4. 核心词汇对照表

`AGENTS.md` 规定的 graph-core 概念表是：**Object / Slot / Edge / Group / Block / Doodle / Command / Event / Value / Status**。三份聊天里用的是另一套措辞（Var / Process / Port / Frame / Subgraph / Cell…）。下表做对齐，并标出没收口的地方：

| 法定名 | 聊天中的叫法 | 当前理解 | 状态 |
|---|---|---|---|
| **Block** | TextCell、md 便利贴 | 内容层文本，可多开，**数据上永不合并**；散的未定义文本框 = 只有 Block，只做人的外置记忆，不进求值 | 【倾向】多开不合并已共识；正式化时"副本"落在 Block 还是 Object 身上，见待定 O-2 |
| **Object** | Var、Process、Subgraph、FormalObject、Cell(kind=node/var) | 语义层记录的统称，`kind` 是**开放字符串**不是封闭枚举（"一切皆块，区别只在契约"），可带 `eval` 契约 | 【倾向】kind 开放已共识；formal 是状态位还是种类差，见待定 O-1 |
| **Slot** | Port、端口 | Object 上的契约（不是独立的"东西"），方向 in / out，可能含 stock 角色 | 【倾向】槽类型四件套已定（见下）；stock/buffer 是不是 Slot 的一种角色，待定 O-4 |
| **Edge** | Edge | 一等公民：有 id / type / props / status；`delay` 字段预留（v1 不求值）。语义上边不是变量、不是全局注册表 | 【已定】数据结构层面 |
| **Group** | Frame(formal:false)、视觉组 | 纯视觉组合，求值不可见，边可任意穿透 | 【倾向】 |
| **Doodle** | **所有聊天中均未出现** | 推测为自由笔迹/涂鸦层（黑板上的粉笔画痕），但无人定义过 | 【待定】见 §6 D-1 |
| **Command / Event** | Command / Event | 唯一写路径的载体与广播；UI、Agent、插件同源 | 【已定】方向；命令清单未冻结 |
| **Value** | payload、权 | 边上传的载荷；一根边传一个值，值可以是复合结构（见待定 O-3） | 【待定】 |
| **Status** | fresh / stale / undefined / manual / error / orphan | 见 §5 | 【倾向】集合与规则大体有共识，v1 裁剪未定 |

**槽类型四件套【已定】**：`number | text | quantity | ref`，禁止发明第五种。注意它与"流股 record 一根线"的张力尚未裁决，见待定 O-3。

## 5. 执行与状态模型（概览，细节留给数据模型文档）

### 5.1 status 传播的精神

让残缺的图也能部分跑起来，靠的是 status 沿边传播。聊天中达成的规则草案【倾向】：

- **undefined 传染**：任一必需输入为 undefined → 输出 undefined，但不锁死整图；
- **manual 阻断且供能**：手填值不被上游覆盖，并向下游传播 fresh——这是"上游还没定义，我先手填一个数，下游照样跑"的关键，也是对话树场景"保留 user 回答、只重跑 agent 回答"的同一机制；
- **error 传染但携带来源**（`causedBy`），方便定位；
- **orphan 不阻断求值**：失去溯源但值仍有效，UI 标黄。

v1 实际落几种、stale 是否只在懒求值时出现，待定（§6 E-2）。

### 5.2 时间模型

- 必须支持环（人员调度、反馈环、循环物流全是环）【聊天共识】。手段是 tick + delay 边：成环处插"读上一 tick 的值"，拓扑排序时剪掉 delay 边，剩下的是 DAG。
- **但 v1 不实现 delay 边求值**【已定，AGENTS.md】，只在数据结构预留字段（R 系列）。v1 的环只能"画出来并标注"，不能跑——这个口径要在交互文档里对诚实性做设计（提示"要真反馈，等步进功能"）。
- multi-rate 子图、异步电池（LLM 节点挂起恢复）同样只预留字段，v1 不做【已定】。

### 5.3 求值触发

聊天中提出三种节点求值模式共存【待定，§6 E-1】：

- `once`：执行一次即冻结（LLM 调用、外部命令）；
- `reactive`：上游变了才重算（Grasshopper 式）；
- `tick`：每个时间步都算（Simulink 式）。

推/拉之争在有 tick 之后降级；v1 建议全量求值 + 按 status 剪枝（实现成本接近全量、性能接近增量）【倾向】。

## 6. 待定议程

只摊问题与候选方向，不做裁决。编号仅为本文档内部检索方便，**不是**将来的 D-/U-/R- 正式编号（那套编号归将来的决策台账，见 §9）。

### O. 对象模型终局

- **O-1 formal 是状态位还是种类差？** 两套模型没收口。方案甲（chat4 尾段）：统一对象表 + `formal: boolean`，"抓"= 把 formal 翻成 true 并补契约；方案乙（chat2）：内容层永远是 Block、语义层永远是 Object，正式 = 语义层有记录，两层靠副本+回链关联。`AGENTS.md` 的"独立副本 + origin 软回链"更接近乙，但甲的"正式性是形容词不是名词"在解释边的正式化、复制粘贴副本时更顺。需要一次专门讨论收口。
- **O-2 正式化的"副本"是什么粒度？** 整块复制、还是"一段文本被四个对象引用"时各复制各的片段？副本之后用户改原文，是否提示"要不要同步更新副本"（注意：这不是实时跟随锚定，是单次手动动作，与禁止清单不冲突，但要不要做未定）。
- **O-3 槽四件套 vs record 流股。** 四件套【已定】禁止第五种槽类型，但 Aspen 式流股（一根线传 `{T, P, F, x[]}`）聊天中强烈要求。候选裁决：四件套是**槽的类型标签**，`quantity`/`ref` 的值内部允许结构化嵌套（类型嵌套 ≠ 槽种类）；或 v1 先不支持复合载荷，流股后做。此条不定，数据模型写不下去。
- **O-4 stock / buffer 放在哪？** 用户原始诉求是"打组以后自带一个可正可负的存量变量数组来缓冲"。聊天方案：它是 Var/Slot 的一种角色，不是新物种。待确认。
- **O-5 Group 与 Subgraph（封装）是同一种东西的两个状态，还是两种东西？** chat4 用 frame 统一吸收（`formal: false` = GH 的 Group，`formal: true` = Cluster/Subsystem，有端口和命名空间）；chat2 / AGENTS.md 词表只列了 Group。封装（有对外端口、求值可见、边不许穿透）的能力肯定要，挂在哪待定。
- **O-6 变量作用域。** chat4 提议 `scope: global | frameId | nodeId`（变量不住在任何块里，只声明可见范围，"第一个出现它的块不负责定义它"）。方向顺，未确认。
- **O-7 违规边（穿透 Subgraph 的线）允不允许存在？** chat4 提议允许存在但标记 `violating`，求值仍生效、导出时报警，符合"不阻止只标记"哲学。待确认。

### D. 待定义项

- **D-1 Doodle 到底是什么？** 它出现在 `AGENTS.md` 的法定概念表里，但三份聊天从未讨论。是自由笔迹层？装饰涂鸦？还是别的？需要定义，否则 graph-core 的概念表是空的。

### E. 执行模型

- **E-1 evalMode 三模式（once / reactive / tick）是否成立、默认哪个、粒度是节点级还是图级？** 对话树（跑完即冻结）与流仿真（每 tick 重算）是两种执行语义，同一张图可能混用。
- **E-2 status 集合 v1 裁剪**：六个状态全上还是先上四个（如先不要 stale / orphan）？orphan 在"副本+回链"模型下还存不存在（锚定被否决后，orphan 的触发条件变了）？
- **E-3 历史快照**：环形缓冲多大、手动打点（pin）怎么做——"过程即结果"的兑现在这里，但存储爆炸要防。
- **E-4 成环在 v1 的诚实口径**：画环允许、跑环不做，UI 上说什么话。

### C. 内容与正式化交互

- **C-1 "抓"的手势分解是否采纳**：tovar（声明变量）/ promote（封装成块）/ insert-prefab（跳过草稿）/ connect / group 五个原语，禁止一个万能"抓"【倾向，待确认】。
- **C-2 hover 候选 vs 直接转正**：鼠标指过去高亮 token 只是候选，确认键才是声明。直接转会把错选、单位、注释全变成图节点，图会脏死【倾向】。
- **C-3 位置猜测的确认交互**：抓取瞬间浮出轻量确认（`[输入] [输出] [参数]` 小 chip，默认高亮猜测项），不做全自动【倾向】。
- **C-4 类型怎么编辑**：嵌套类型（向量、流股字段）用文本/表单编辑，不做"把列向量拖进方括号"的空间操作（那会把类型构造变成几何操作，后端复杂度爆炸）【倾向】。

### U. UI 与交互

- **U-1 v1 面板范围**：北极星是 9 区 15+ 面板（中央画板、agent CLI、多终端、设计树、图层、命令历史、调试、agent 对话、功能面板、md 编辑器、copilot、git/插件栏），那是 3-5 年的量。v1 砍到"中央画板 + 右侧单面板 + 底部命令行"三区【倾向】，具体边界待定。
- **U-2 渲染层**：React Flow（DOM，上手快，500+ 节点掉帧）起步，何时切 Canvas / PixiJS（视口裁剪，几千死块的量级需要）？切换判定标准未定。注意这是改起来代价极大的选择。
- **U-3 快捷键**：v1 子集已定（左键选/框选、中键平移、滚轮缩放、右键菜单、空格整理）【已定】；Rhino 式右键重复/修饰键体系留 v2（需要精细命中测试状态机）【倾向】。
- **U-4 需要文件树面板吗？** 用户自己的"文件树"其实是"块的层级视图"，跟真实文件系统关系不大【倾向不做，待确认】。

### S. 存储与持久化

- **S-1 v1 存储**：IndexedDB 存整个项目 JSON 起步【倾向】，配显眼的"导出 JSON 快照"按钮（清浏览数据会连 IndexedDB 一起清；`localhost` 换端口 = 换源 = 数据互不相通，要固定端口）。何时迁 SQLite：模型稳定 + 大图性能痛了再说，中间靠 `ProjectRepository` 接口隔离。
- **S-2 导出三态**：JSON（备份/调试/可 diff）、md（给 Obsidian/git 的只读单向投影，导出即快照）、将来的 SQLite。主存储永远不是 md。

### A. Agent 与生态

- **A-1 Agent 插件化的边界**：agent 是插件（对话窗口 + 模型适配器 + 工具调用器 + Graph API Client），内部协议自定义，MCP 只做外部 adapter【倾向】。时机未定。
- **A-2 权限与限流**：对话树场景里，agent 可被授予元操作权限（新建 agent、单步生图），每次要有次数和流量限制，防止抽风新建 subagent 把钱烧完。机制空白。
- **A-3 预制块（prefab）格式**：给 agent 的高层词汇表（一次调用生成 8 节点 6 边），也是将来电池生态的雏形。格式未定。
- **A-4 python 电池**：是未来的插件运行时，不是核心架构依赖；浏览器形态做不了（需要子进程），这是第一个真正需要桌面壳的信号【倾向】。

### G. 分发与工程

- **G-1 成品形态**：Web 端即成品（含 PWA），不做桌面壳【已定】；上壳的信号：要起子进程、要浏览器保留键、要托盘/全局快捷键、要给别人无脑分发——一个都没有之前不动。
- **G-2 分发三线（将来）**：npm 包（免签名干净线，机制：包管理器下载不带 Mark of the Web 且不经双击启动链）/ GitHub Releases 安装包（无签名 + README 教两步绕过）/ 源码仓库。三条线 $0，由同一仓库 + 一次 tag 经 GitHub Actions 自动产出【倾向，聊天共识充分】。
- **G-3 开源与许可**：建议分层——数据格式规格（schema）公开文档化、核心引擎倾向开源、UI 层可后置。借鉴别家思路自己重写不受任何许可证约束；直接复制代码才涉及传染（GPL/AGPL 系要小心）【倾向】。
- **G-4 CI**：GitHub Actions 对公开仓库免费，Tauri/electron-builder 有现成 action。自用阶段不急。

## 7. 已否决方向与已知坑（墓地）

这些方向在聊天中被推演过又被否决，**重新提出前先读这里的死因**：

| 方向 | 死因 | 出处 |
|---|---|---|
| 万物皆 md / md 当存储 | md→图→md 往返不可能无损；status 写进文件则每次求值全部文件被改写、diff 全噪声；删个标题整个层级重组且无法检测错误；md 的数据模型是树，表达不了图 | chat4 |
| "底层 md，跑时编译，跑完落盘 md" | 同上，编译单向前提被运行时状态写回违反 | chat4 |
| Python + FastAPI 本地服务后端 | 单客户端场景下服务化是纯负债；改回库形态 | chat4 中段提出、后段推翻；AGENTS.md 定为 v1 决策 |
| 正式块与原文的实时跟随锚定（双向同步 / tokenId / 指纹重定位） | 改为独立副本 + origin 软回链 | AGENTS.md 禁止清单（晚于 chat4 的 anchor 方案） |
| 万能"抓"手势（一次既发明变量又发明块又重排文本） | 拆成 tovar / promote / insert-prefab 等原语；宏可以笨，命令必须干净 | chat2 |
| promote 时重排散文本 | 正式化只新增语义记录，不碰用户文本；重排是布局命令，另一件事 | chat2 |
| pickle 式序列化 | 跨版本迁移与安全性都差（Orange 的 .ows 教训）；用显式 schema + 版本号 | chat4 |
| hover 直接转正为正式变量 | 图会脏死；候选与声明必须分开 | chat2 |
| 平行标量线当流股默认（温度一根线压力一根线） | 默认一根线传复合值；拆字段用 field 选择器 | chat2 |
| 在应用层做"统一五个工具的通用元工具" | Yahoo Pipes / Quartz Composer / LabVIEW 的历史规律：应用层统一全失败或小众化；收缩为个人外置思维系统 | chat4 |
| 用操作语法强制用户"正确建图" | 终点是古板求解器；引导用默认和糖，不用锁 | chat2 |
| 单件/装配体两套数据结构（SW 病） | 扁平表 + parent 指针 + 递归嵌套天然统一，是同一结构的不同深度 | chat4 |
| 空格键同时触发重新布局 + 后端整理 | 两个不相关的开销绑在一起；空格只管布局，后端整理 idle 静默做 | AGENTS.md 禁止清单 |

## 8. 场景与验收画像

四个驱动场景（详见 `work/docs/a_ux_description.md` 与聊天原文），各自的验收含义：

1. **MCM 黑板**（人在纸上）：新建自由文本框打字 → 画框画箭头（此时纯空间语义，零程序嵌套）→ 复制粘贴出副本保护原件 → 对副本做一次正式定义（前端算包络从属、内外、箭头指向；悬空箭头不报错只提示，框外不受影响）→ 声明变量 → 接线 → 手填一个值看下游变 fresh。这条链路是 v1 的**黄金路径**。
2. **逆向化工流程**（agent 图搜索）：残破不完备的图，agent 走 Command API 补全；化工预制块的 `eval` 对它就是仿真引擎。验收 = 无头脚本能建图、连块、跑、读数。
3. **科研对话树**（多 agent 编排）：树状启发式对话，分支 / 剪枝 / debate / merge / clone 换源重跑（保留 user 回答 = manual 节点不重算）、subagent 分发、多态继承、权限限流、可挂第三方工具（opencode 等，需要子进程 = 桌面壳信号）。这是暴露执行模型（once 模式）和权限设计最多的场景，实现靠后。
4. **无头脚本**（一票否决）：见 §3.4。

用户画像（第一天）：自己跟自己讲话的人、两三人同步的人、从纸/白板过来的人——他们第一天不想当仿真工程师，若用电池/端口教育他们，他们会关掉软件去用纸。
