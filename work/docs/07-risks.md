# 07 — 已知风险与坑

> 本文收录已预见的具体风险、历史案例教训、以及 vibe coding 特有的失控模式。每条含"现象/后果"与"对策"。对策已落地的标注对应决策编号。

## 1. 数据与存储类

| # | 风险 | 对策 |
| --- | --- | --- |
| 1 | **IndexedDB 绑定 origin**：dev 端口一变（5173→5174），数据"消失"；无痕窗口/清浏览数据直接灭库 | 端口锁死 strictPort、不用无痕、导出 JSON 按钮做显眼（D-41） |
| 2 | **裸字符偏移定位**：文本一编辑，所有引用错位 | Anchor 三级机制（tokenId → 指纹 → orphan），禁止裸偏移（D-12，AGENTS 禁令） |
| 3 | **md 当存储的三宗罪**：运行时状态写回污染 diff；往返不可能无损（用户排版被"格式化"）；删个标题全图错位且无法检测 | md 只做内容层与导出投影（D-04/05，否决清单） |
| 4 | **pickle 式序列化**：对象结构直固化，跨版本迁移与安全性双输（Orange `.ows` 教训） | 自定义 JSON schema + `schemaVersion` + 迁移函数链（D-14/R-09） |
| 5 | schema 必然演进，老存档打不开 | 从第一天存版本号；每次改 schema 写迁移函数（D-14） |

## 2. 架构类

| # | 风险 | 对策 |
| --- | --- | --- |
| 6 | **状态塞进 React 组件**（vibe coding 第一死法）：`useState([])` 存图，之后加 agent/undo/多窗口全部失控 | 图数据只在 graph-core；React 走 Command Bus（AGENTS 纪律 1/2） |
| 7 | **平台判断散落**：`if (window.__TAURI__)` 到处出现，桌面壳一加就是大改 | 五条缝关进 HostBridge/ProjectRepository，只查能力不判环境（D-25/26） |
| 8 | **服务化冲动**：凭空造一个 localhost 后端，多出序列化/断线重连/两套日志 | 库形态；服务化三信号一个都没出现前是纯负债（D-24） |
| 9 | **先壳后内核**：桌面壳做完发现内核装不进去 | Web 即成品形态，壳是最后套的皮（D-27，否决清单） |
| 10 | **面板爆炸**：9 区域 15+ 面板的状态同步是指数级复杂度（选中节点→设计树高亮→md 面板联动→agent 上下文…） | v1 锁死三区域（D-30）；北极星面板逐个按痒加 |
| 11 | **外部框架传染**：核心对象继承 agent 基类、数据格式被库绑死 | 外部框架只在 adapter 层（D-21，AGENTS 纪律 7/8） |
| 12 | **插件自发明格式**：每个电池自己造一套对象描述 | 统一 ComputePlugin 契约 + kind/ports 契约（D-08/R-08） |

## 3. 交互与性能类

| # | 风险 | 对策 |
| --- | --- | --- |
| 13 | **浏览器保留键**：Ctrl+W/T/N/L、F12 拦不住，误触关标签页 | v1 键位设计避开这些组合（D-33；桌面壳阶段自然解除） |

| 16 | **抓块全自动意图识别出错**：嵌套时位置歧义（对父在左、对祖父在右），改错成本高 | 位置识别只作默认值，chip 确认一次（D-31） |

## 4. Agent 类

| # | 风险 | 对策 |
| --- | --- | --- |
| 18 | **agent 直接改库/改文件**：改崩无人拦 | 只走 Command API，schema 校验 + undo 兜底（D-19/20） |

## 6. 历史案例速查（为什么这些决策长这样）

| 案例 | 教训 | 本项目对应决策 |
| --- | --- | --- |
| Yahoo Pipes / Quartz Composer | 应用层做"通用节点工具"必死：太通用则谁都服务不好 | D-01（个人自用先行） |
| Jupyter / ONNX / MIDI / ROS | 活下来的统一都发生在**窄边界协议**，不是计算模型本身 | Command API / plugin 契约设计取向 |
| Obsidian | md 当真相源 → 语义表达力天花板 + 改残即碎；但"闭源软件 + 开放格式"成立 | D-04/05；D-40 |
| Blender | 扁平表 + ID 引用支撑任意嵌套；DNA 自描述让几十年前的存档今天能开；depsgraph 脏传播是 status 机制的工业版 | D-06；D-14；03 §5-6 |
| Scratch | project.json 扁平字典 + parent/next 指针的极简可行性 | D-06 |
| Orange | 三分库（canvas-core/widget-base/本体）的分包正确性；pickle 存档的反面；Qt 选择导致 GPL 被动传染 | D-35；否决清单；D-40 许可证分轴 |
| Codex CLI | "TS 原型 → 成熟后按需重写成单二进制"是官方走过的路；分发障碍（要求用户有 Node）是真实痛点 | 技术栈不锁死在 TS 的教条上；D-37 npm 线 |
| OpenClaw | md 作为"人可编辑的意图层"+ 底下结构化引擎，百万行级验证；单网关多渠道 = 单引擎多客户端同构 | D-05；D-24 的服务化三信号参照 |
| opencode | 客户端-服务器拆分服务多客户端并存场景——也划清了本项目**何时不需要**服务化 | D-24 |
| SolidWorks | 零件/装配体/草图三分 = 三套求解器胶水粘连；虚拟零件证明"不必把结构映射到文件系统" | D-09；D-29 |
