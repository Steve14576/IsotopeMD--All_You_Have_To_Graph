# 00 — 项目宪章：IsotopeMD 是什么

> 本文只回答"是什么、为什么、边界在哪"。技术决策见 01，架构形态见 02。

## 一句话定义

**可执行的渐进形式化黑板**——一个以自由文本为入口、以渐进形式化图为核心、支持状态传播和可选计算插件的个人外置思维系统。

## 缘起

直接触发点：MCM 这类竞赛中"策略管理混乱、算法研究方向混乱、人员调度混乱且相互耦合"的地狱场景。更广义的野心是做一个比 Obsidian 高一个量级的外置大脑——Obsidian 本质是 md 编辑器加不支持图语法的渲染，而这里要的是**活的黑板**：出外勤谁替谁、谁在谁不在；Aspen/Simulink/Grasshopper 的草稿层；多层 UML 拓扑；控制流要结合"人的心情"；甚至开发菜谱——**过程即结果，打完草稿，过程本身就是产出**。

## 三个核心特征（与一切现有工具的分界线）

1. **过程即结果**。不是"建好模型→运行→拿结果"，而是草稿在活着的过程中被使用、被查阅、被修改；状态轨迹本身就是产出（"谁替谁"的调度史 = tick 快照序列，不需要"算出"什么）。
2. **节点内严谨性可选、可插拔**。与 Aspen/Simulink 正好相反：图的拓扑服务于人的思考与调度，节点严谨性是后加的"电池"（python 脚本、预制节点、手填值都行），不在 v1 核心承诺内。
3. **异质流的强类型自由度**。流股可以是数字、人、"心情"这种软变量；图结构不在乎流的物理意义，只在乎状态怎么传递、层级怎么嵌套。

三者合起来：一个允许**非正式、部分严谨、可实时更新**的活状态图，用作个人/小团队的运营认知外脑。

## 它不是什么（防止野心漂移）

- 不是 LangGraph 可视化器；
- 不是 Simulink/Aspen 替代品（专业计算交给外部电池）；
- 不是 Markdown 编辑器，也不是 Obsidian 插件；
- 不是通用 Agent IDE；
- 不是科学计算平台；
- 不是"统一 Grasshopper+Scratch+Obsidian+Simulink+LangGraph 的元工具"——那个版本在历史上（Yahoo Pipes / Quartz Composer / LabVIEW 的困局）已被判死刑，本项目是它的反面：先对自己这一摊烂事管用，通用化是验证之后的事。

## 三条入口（最终汇合到同一个图模型）

| 入口 | 路径 |
| --- | --- |
| **人** | 在黑板上写死文本 → 框选 → 抓成正式对象 → 连线 → 手填/求值 |
| **Agent** | 通过 Command API 直接生成/修改正式图（跳过死文本阶段；高层词汇表 = 预制模板） |
| **代码** | 通过插件/脚本 API 创建电池与求值器 |

三条路径共用同一套 Command API（见 D-19），因此 undo/审计/校验对三者同时生效。

## 差异化根基

"死块 → 抓块 → 正式块"的**渐进形式化（progressive formalization）**是整个设计里最有价值的东西：传统节点工具要求写下任何东西之前就想清楚它是什么类型，这扼杀了草稿性；本项目允许"先随便写，想清楚了再抓"，并允许残缺草稿部分求值（悬空不报错，只是 undefined 传染）。这个根基必须守住，任何新功能不得以牺牲它为代价。

## 成功判据（v1 最小闭环）

```
双击黑板写死文本 → 框选其中一段 → 抓成正式对象（出现端口）
→ 连线 → 手填一个 manual 值 → 下游 status 从 undefined 变 fresh
→ 保存 → 重开 → 加载 → 撤销/重做正确
```

这条链跑通且自己连续用几周不嫌烦，架构就是对的（详见 06-roadmap §2 验收标准）。
