# 语言智能体树搜索（LATS）方法论提炼

> 提炼自《Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models》（ICML 2024，见同目录中文翻译稿）。
> 写法约定：与姊妹篇《自一致性方法论提炼》一致——前半部分只讲**方法论**（怎么用、什么时候用、什么时候别用），**原理**（为什么有效）单独拎到后半部分。行文中"说人话"优先，结论与数据处保持严谨并附实验出处。
> 定位速记：**自一致性是便宜档（平铺采样 + 投票），LATS 是贵价档（树搜索 + 环境反馈 + 反思）。先上便宜档，不够再上这套。**

---

## 0. 一句话总览

**让语言模型像下围棋一样解题：把"思考 + 行动"组织成一棵搜索树，每一步采样多个候选动作，用环境的真实反馈给各分支打分，砍掉坏分支、深挖好分支；失败的整条路写一段"检讨"存起来，下次尝试自动避开同样的坑。**

- 零训练、零微调，纯推理时编排框架；模型一人分饰三角：**智能体**（干活）、**价值函数**（打分）、**反思者**（总结教训），环境当裁判。
- 它统一了三条此前各自残缺的路线：CoT/自一致性只会闷头想（无行动）；ReAct 能行动但一条道走到黑（无规划）；ToT/RAP 会规划但闭着眼搜（无外部反馈）。
- 一句话总纲：**把算力集中到有希望的方向，用真实反馈砍掉没希望的分支，用反思避免重蹈覆辙。**

## 1. 适用条件（先查这几条，不满足就别用）

1. **任务必须可回退。**这是硬前提：要能"悔棋"回到之前的任何状态。对语言模型任务，回退 = 把之前的上下文重新喂一遍，几乎免费；适用于编程、信息检索、网页导航、工具调用等文本交互任务。不可逆环境（真实下单、发邮件、物理机器人动作）不适用。
2. **环境必须能给可观察的反馈。**测试通过/失败、编译器报错、检索返回内容、购买是否达成——有真实反馈，LATS 的核心优势才成立。完全没有反馈的纯推理任务只能退化成 CoT 版 LATS，收益缩水（0.62 vs 带环境版 0.63~0.71）。
3. **任务要够难，配得上开销。**一次 LATS = 几十次模型调用 + 若干次环境查询。论文自己的建议：编程这类难题、或性能优先于效率的场景才值得；简单任务用 ReAct 甚至自一致性就够了。
4. **环境反馈质量要有保证。**论文实验用的是高质量反馈（oracle 设定：环境如实告知答案对错）。反馈又慢又噪的现实环境，收益会打折。
5. **错误得是"可被环境裁决"的。**环境的裁决（测试、搜索事实、购买结果）是搜索的指南针；环境判不了对错的任务，树搜索失去方向。

## 2. 方法论：操作流程

### 2.1 准备工作（用之前先定义这四样）

1. **基础提示模板**：有环境交互的任务用 ReAct 式（思考/动作/观察交错）；纯推理任务用 CoT 式。附 3 个左右的少样本示例。
2. **动作空间**：明确智能体每步能做什么。例：问答任务 = `search[实体]` / `lookup[关键词]` / `finish[答案]`；网购 = `search[查询]` / `click[按钮]`；编程 = 提交一份完整实现。
3. **环境接口**：执行动作 → 返回观察（文本形式）。回退靠重新拼接上下文实现。
4. **裁决机制**：什么算成功（测试全过 / 完成购买 / 环境确认答案正确）。裁决越客观，搜索越有方向。

### 2.2 主循环（六个操作，白话版）

从根节点（原问题）出发，反复执行直到成功或预算耗尽：

1. **选择**：从根开始，每层按 UCT 值（= 节点价值 + 探索加成）挑子节点，一路走到叶。UCT 会自动偏向"价值高"且"还没怎么被挖过"的分支。
2. **扩展**：在叶节点采样 $n$ 个动作（温度采样，保证多样性），每个动作交给环境，拿回观察，长成 $n$ 个新节点。
3. **评估**：给每个新节点打分。价值 = $\lambda$ × LM 打分 + $(1-\lambda)$ × 自一致性得分。**铁律：打分必须发生在拿到环境反馈之后**（让模型看着观察结果评，不许闭眼评），并要求模型最后输出一个 1–10 的分数。
4. **模拟**：从当前节点沿高价值方向继续向下扩展，直到抵达终止状态（成功/失败/深度上限）。
5. **回传**：拿终局奖励沿路径逐节点更新价值和访问次数，供下一轮"选择"使用。
6. **反思**：轨迹失败时，把失败轨迹 + 结果喂给模型，让它写一段"错在哪、下次怎么改"的文字反思，存入记忆；后续所有尝试的提示里注入这些反思作为额外上下文。

**收尾**：搜索结束（成功即停，或预算耗尽）后，取价值最高的轨迹的答案作为最终输出。

### 2.3 参数怎么定（论文默认值速查）

| 参数 | 含义 | 推荐值 | 说明 |
|---|---|---|---|
| $n$ | 每步扩展的候选动作数 | 5 | 成本/性能的主旋钮；$n=1$ 时退化成"多次尝试的 ReAct"档位 |
| $w$ | UCT 探索权重 | 1 | 调到 0.5 会变差，2.0 收敛快但不更好 |
| $\lambda$ | 价值函数中 LM 打分权重 | 问答/数学 0.5；编程/网购 0.8 | 反馈越客观稀疏，越依赖 LM 打分 |
| $k$ | 总轨迹预算 | 问答 50；编程 8；网购/24 点 30 | |
| 深度上限 | 单条轨迹最长步数 | 问答 7（实测 4 步基本够）；编程 8；网购 15；24 点 5 | 宁短勿长（见 §3.6） |

**编程任务的专门配方**：每个动作 = 一份完整实现；跳过"模拟"步骤；用 LM 先生成 4–6 条合成测试当中间反馈，把真实测试通过率当回传奖励；跑 8 轮迭代；最后取最高价值实现交真实测试。

### 2.4 档位选择（便宜到贵的升级路径）

1. 单次 CoT/ReAct → 2. 自一致性（采样投票）→ 3. Reflexion（单轨迹 + 反思重试）→ 4. **LATS（树搜索 + 反馈 + 反思）**。
逐级加钱，逐级变强。**先用低档确认"模型基本会做"，低档卡住了（票型分散/反复犯同一错）再升档。**

## 3. 方法论：红线与反直觉要点（不要做的事）

### 3.1 不要以为"把现成方法拼起来"就行

把 ReAct 提示直接套到 ToT/RAP 上做简单拼接，效果比纯内部推理还差（ToT+ReAct 0.39、RAP+ReAct 0.54 vs 纯推理 0.60，表 3）。**加了环境交互反而更糟**——适配决策场景需要重新设计价值函数与节点结构，拼接无效。这是全文最反直觉也最重要的教训。

### 3.2 不要去掉 LM 价值函数（命门）

只靠环境的终局奖励（稀疏、通常是二值的）引导搜索，性能从 0.63 暴跌到 0.37（−0.26，表 8）。环境反馈再好，也必须有一个"预判局面好坏"的打分器把信号提前、加密，搜索才有方向。

### 3.3 不要把 MCTS 降级成 DFS/剪枝

去掉选择与回传、改用 ToT 式的低价值分支剪枝：掉 0.21（0.63 → 0.42）。有原则的探索-利用平衡不是可有可无的装饰。

### 3.4 不要神化反思

反思有用（去掉掉 0.05）但不是万能药：在 WebShop 这类复杂环境里，生成的反思常常笼统、缺乏信息量，智能体仍会困在局部极小值（Reflexion 与 ReAct 采样同数轨迹时性能接近）。**反思是辅助信号，环境反馈才是主信号**；反馈客观的任务（编程：有测试报错）反思质量高，主观任务（逛网站）反思质量低。

### 3.5 不要在没有回退能力的环境里用

MCTS 依赖反复回到早前状态重试。真实支付、消息推送、物理动作等不可逆操作场景，框架前提不成立——别硬套。

### 3.6 不要把深度拉太长

HotPotQA 上大多数问题 4 步内可答，深度从 7 砍到 4 只轻微掉分；步数拉太长反而把智能体逼进局部极小值。**深度上限宁紧勿松。**

### 3.7 不要指望它便宜

$n=5$、$k=50$ 意味着成百上千次模型调用。预算敏感时降 $n$（$n=1$ 即回到多试几遍的档位）或减 $k$，但要明白此时你本质上已经退回到更低档的方法，不如直接用低档。

## 4. 方法论：变体与推广

1. **纯推理变体**：无环境任务用 CoT 作基础框架，Game of 24 上超过 ToT/RAP（0.44 vs 0.20/0.40）——价值函数里的自一致性项在没有环境反馈时顶上来当裁判。
2. **内外结合变体（推荐套路）**：先用 CoT 提示凭记忆直接答，失败了再切 ReAct 提示动用工具检索。HotPotQA 上最高分 0.71 就是这个组合。模仿人类：先凭脑子答，答不出再查资料。
3. **代码任务的通用配方**：见 §2.3。核心思想：**把"测试"当作环境**，任何可自动判对错的裁判（lint、类型检查、单元测试、仿真）都能充当 LATS 的环境。
4. **与自一致性的继承关系**：SC 的投票思想被收编为价值函数的一个分量（同一状态被多次采样到的动作更可能对）。**SC 证明了"多试有价值"，LATS 解决"怎么聪明地分配多试的预算"。**
5. **反思记忆可跨任务复用**：失败轨迹 + 反思是纯文本，天然可存入长期记忆库，理论上可跨会话复用（论文内是单次任务内使用）。

## 5. 原理（单独拎出来，为什么有效）

### 5.1 为什么用 MCTS：探索与利用的平衡

贪心会困在局部最优，随机采样浪费预算。UCT 公式 $\mathrm{UCT}(s) = V(s) + w\sqrt{\ln N(p)/N(s)}$ 前半项偏向"已验证的好分支"（利用），后半项偏向"还没怎么试过的分支"（探索，访问次数少则加成高）。这保证算力既集中又不僵化——这是 BFS/DFS/束搜索都给不了的。

### 5.2 为什么"可回退"是整个框架的地基

经典 MCTS 需要环境模型来悔棋（强化学习里往往要专门训练一个）。语言模型任务绕开了这个难题：**状态就是文本上下文，回退 = 复制粘贴历史输入**，无需任何模型、零成本。没有这个性质，MCTS 搬不过来——所以论文把"利用回退性"称为被社区忽视的特性而非局限。

### 5.3 为什么评估必须在环境反馈之后（与 ToT 的本质区别）

已有工作证明语言模型无法可靠地自我纠正纯内部推理（Huang et al., 2024）。ToT 式"闭眼自评"打分，本质是让幻觉给幻觉打分；LATS 让模型看着环境返回的观察（检索到了什么、测试挂了哪条）再评，打分才有事实锚点。这就是为什么简单拼接失败而 LATS 成功：不是拼上交互就行，**价值函数的信息流方向必须改成"环境 → 评估"**。

### 5.4 为什么反思是"便宜的强化学习"

标量奖励（对/错）信息量极低，且只在终局出现。反思把失败转化为**语义梯度**：一段文字说明错因与改进方向，通过上下文学习注入后续尝试，等效于"不用梯度下降的经验学习"。边界也清楚：反思质量取决于模型能否从轨迹中真正定位错误，环境越复杂主观，反思越容易流于空泛（见 §3.4）。

### 5.5 为什么自一致性被塞进价值函数

在同一状态被独立采样到多次的动作，相当于经过了"小范围投票"，正确概率更高。在环境反馈稀疏或滞后的地方（还没走到终局、或纯推理任务），这一项补上了打分的另一半信息源。消融证实：Game of 24 上去掉自一致性项（$\lambda=1$）从 0.44 掉到 0.40（表 13）。

### 5.6 为什么它反而比 ToT/RAP 省 token

直觉上树搜索更贵，但成功时平均 token 更少（173k vs RAP 176k vs ToT 210k，表 9）：LM 价值函数把搜索导向高价值区域，**更快抵达成功终局、更早停止**，少走弯路抵消了单步开销。样本复杂度同为 $O(kn)$，效率差异来自"走弯路多少"。

### 5.7 更大的图景：test-time compute 的三要素装配

这条线的演化：自一致性证明"推理时多花算力能换准确率"；LATS 进一步证明算力要花在刀刃上，需要三件装配——**搜索**（MCTS 分配预算）、**交互**（环境反馈当裁判）、**反思**（经验跨试次复用）。三者缺一，消融数据都会明显下滑（表 8）。这也是"System 2 式语言模型"路线的代表性工程实现。

## 7. 局限（诚实申报）

1. **贵**：几十到上百次模型调用 + 环境查询；靠 $n$、$k$ 旋钮控制，但降到底就等于退回低档方法。
2. **回退假设**：不可逆环境不适用；现实中不少任务"覆水难收"。
3. **反思质量不稳定**：复杂主观环境中反思容易空泛，智能体仍可能困在局部极小值。
4. **依赖反馈质量**：论文的强结果部分建立在高质量（oracle）反馈设定上；反馈又噪又慢时收益打折。
5. **超参数按环境调**：$\lambda$、$w$、深度上限在不同任务上的最优值不同（问答 $\lambda=0.5$ vs 编程/网购 $\lambda=0.8$），换环境需要小规模调参。

## 8. 一页速记卡

```text
用：  可回退 + 环境有真实反馈 + 任务够难 + 预算充足
做：  选→扩→评（先拿反馈再打分）→模拟→回传→失败写反思，循环到成功
配：  n=5、w=1、λ=0.5~0.8、深度宁紧勿松；编程任务拿测试当环境
忌：  现成方法硬拼接 / 去掉 LM 打分 / 闭眼自评 / 不可逆环境硬套 / 拉长深度
记：  算力集中到有希望的方向，真实反馈砍坏分支，反思避免重蹈覆辙
```
