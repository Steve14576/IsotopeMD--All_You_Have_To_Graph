# 08 — 场景压力测试：12 个第一人称现场记录

> 本文是一次对抗性验收：以 12 个互不相同的真实使用场景，对截至当前（D-01~D-52 + 03 schema + 04 交互）的架构做沉浸式推演。
> 方法：第一人称代入，流程尽可能长，刻意包含非线性返工与结构性重构；不预设自信——问题在叙事中以"后知后觉"的方式被撞上，而非事后罗列。
> 每个场景标注：传统对标工具（Grasshopper / Simulink / n8n / Aspen / Orange）在同一场景会死在哪。
> 撞出的缺口统一编号 **G1–G15**，最终汇总于 §结论·缺口台账，并给出裁决分级（v1 必修 / 容忍延后 / 定位边界）。

---

## 现场 1：MCM 四天，调度地狱

我是队长。第一天晚上，我在黑板上疯狂打字：队员名单、每人擅长的方向、比赛规则要点、几段乱七八糟的策略猜想。文本块铺了半屏，死箭头在块之间乱画——"算法组依赖数据组先跑通"这种关系我先用画的，不急着形式化。**这一步活下来了**：死文本 + 死箭头让我在完全没想清楚的时候就能开工，这是 Simulink 绝对做不到的（它要求我先定义每个信号的维度和类型才能画第一根线）。

第二天，我决定把"人"变成正式对象。选中"小王"两个字 → 右键"做成正式块"→ chip 弹出 `[变量][过程][公式][人]…`，"人"被高亮，回车。一块"小王"电池出现，我在里面声明了两个 text 槽：`状态:[在岗]`、`位置:[外勤]`，没有 eval——人不是算出来的，是状态容器。**成立**。

然后我想表达"小王周三下午替小李的班，已确认"。我从小王拖一根线到小李——停住了。这条边上我需要挂属性：日期、时段、确认状态。点开边的属性面板……**没有这个东西**。边在 v1 就是哑线，props 字段存在但没有任何交互入口。

后知后觉（**G4**）：关系自带属性是 D-07 的初衷，但 v1 把它锁在了数据结构里。我的绕行方案：建一个 `替班` 关系电池，两个 ref 槽分别指向小王和小李，日期时段写在块的 text 注释里。**能用，但代价是关系多了就遍地都是关系电池**，图会肿。

第三天早上小王病了。返工开始：删掉两条"替班"关系电池、新建"小王→请假"、把原来小王负责的两个算法方向电池的 ref 输入重新指向小李。我在连线和打字笔记之间来回切换了二十分钟，发现拓扑改错了，Ctrl+Z 往回退——**退着退着把我刚才打的三行笔记也退回去了**。

后知后觉（**G10**）：全局单条 undo 栈把打字和图操作搅在一起。打字按输入爆发合并、图操作按 Command 合并，但它们在同一条时间线上交替。Figma 也是单栈，但 Figma 没有大段文本编辑。这个要么接受并写进文档让用户有预期，要么做"文本层/图层双栈"。**当时没人定过这件事。**

第四天复盘，我想回看"第二天的调度长什么样"——过程即结果啊，调度史就是产出。结果发现：v1 没有 tick 循环，也就没有快照序列；我能做的只有导出 JSON。**G6**：灵魂特性"过程即结果"在 v1 没有机械载体，只有手动快照。这个场景里 Simulink/n8n 会死在"人不能当节点"，Orange 死在 widget 固定；我活下来了，但历史的缺位是真实的遗憾。

## 现场 2：精馏塔草图，回流成环

化工课设。我在文本块里抄了题：进料 F=100 kmol/h，x_F=0.4，要求塔顶 x_D=0.95。然后开始搭流程：`进料` 电池 → `精馏塔` 电池 → `冷凝器` 电池，塔底出料一条支路。一切顺利，直到我要画**回流**：冷凝器 → 回到精馏塔。

连线拖过去的瞬间，系统拦截："检测到成环，这条边设为延迟边（delay）？默认是。"

我愣住了。我不想"读上一 tick 的值"——我又不做动态仿真。我只是想说"这股物流绕回去了，它是个回流"。delay 是时间语义，回流是拓扑事实。我按了 Esc，环没画上。

后知后觉（**G3 + G15**）：成环拦截只给了两个选项（delay / 取消），但草稿里成环常常只意味着"这里有个未解的循环依赖"，既不是时间延迟也不想求值。**缺第三个选项：纯声明边（入 schema、可见、不参与求值）**。Aspen 在这里会死得更早——它要求我先选物性方法、给定全部规格、然后祈祷收敛；我连回流比 R 都还没想好，我只想先画出来。

绕行：我把回流边设成了 delay（反正 v1 不跑 tick，delay 只是个标记），在边上什么都写不了（G4 再次撞脸），只能在旁边放文本块注释"回流，R 待定"。丑，但活。

另一个小坑：塔板数 N 我手填 12 进一个 number 槽；两小时后老师说要 15。改槽 → 下游"理论板效率"相关块自动重算成 fresh——**manual 改值 + 反应式传播在这里非常顺滑，是全场最佳体验之一**。

物流组成怎么表达？`x_F=0.4` 还行，但"进料组成 C4:0.3, C5:0.5, C6:0.2"这种向量/表格式数据，四件套 dtype 装不下。我塞进了一个 text 槽，靠肉眼。这属于 G12 的边界（见现场 5 详述）。

## 现场 3：PID 草稿，撞上"状态"的墙

控制课。我要画一个 PID 控制回路：设定值 r → 控制器 → 执行器 → 被控对象 → 输出 y，y 反馈回 r 比较。反馈环这次我很淡定：成环提示 → 设 delay 边——控制里的单位延迟本来就有物理意义，**delay 语义在这里完美命中**。这是 delay 边设计的平反时刻。

然后我试图声明"积分项"电池：输入误差 e，输出 ∫e dt。我点开 eval 选 builtin……builtin 是无状态纯函数。积分是**状态**，需要跨 tick 累积，而 v1 根本没有 tick 循环。

后知后觉（**G6 第二撞**）：任何带记忆的动力学（积分、队列、存量）在 v1 都只能画出来、写注释说明，不能算。这是 v1/v2 的已知分界，但现场撞上时还是有挫感——我连"单步看一下积分项大概多大"都做不到。

饱和环节：执行器输出限幅 ±10。builtin 函数列表里有 clamp 吗？**列表根本不存在**——03 文档只写了"数值运算"四个字，没有清单、没有表达式语法。

后知后觉（**G7**）：builtin 必须尽快定义一个最小集（至少 +−×÷、abs、min、max、clamp，以及"表达式字符串"的解析方式），否则"能跑流股仿真"的承诺在第一个真实公式面前就违约。

Simulink 在这里死于另一件事：它要求我在画 P/I/D 增益之前就把所有参数定下来、把求解器配对；我敢打赌我最后的 Kp 会是现在的三倍——草稿期我要的是"占位 + 手填"，这里 manual 遮蔽规则再次立功：我先手填 Kp=1 把下游跑通，以后接上"调参器"电池的边时手填自动让位。

## 现场 4：每日简报自动化（n8n 地盘）

我想给自己搭个草稿："每天 8 点 → 抓邮件 → 提取带'发票'的 → 汇总 → 推微信"。五个块一字排开，死箭头先画个大概。

问题很快来了。"每天 8 点"和"收到邮件"是**事件触发**，而我的边全是数据依赖语义——没有"触发"这种边，也没有"等待异步事件"的块语义。我建了一个 kind=`trigger` 的电池安慰自己，但它和下游的边表达的其实是"然后"，不是"传值"。

更深的坑：画到一半我本能地想点"跑一下"——**v1 没有任何真实执行**，没有 HTTP、没有定时器、builtin 也算不了"抓邮件"。我盯着屏幕意识到：这是**草稿黑板**，不是执行引擎。心理落差是真实的。

后知后觉（**G13，定位边界**）：控制流/事件语义不在 v1 世界观里。n8n 在这里的强项恰恰是执行；但 n8n 死在另一处——它的每个节点都必须是真实集成，我还没想好用什么邮件服务、什么过滤器时，n8n 里我连图都画不出来。我这里可以先放一个 text 写着"某种过滤器，回头定"的块。**草稿性是赢的，但要承认执行语义是缺失的维度**，未来电池的 plugin 契约（R-08）是补这个洞的正确位置，不是 v1。

我的绕行：把"时序"用编号注释 + doodle 箭头表达（1→2→3），把每个块当成"未来 n8n 节点的设计卡片"，kind 标记为 `n8n-spec`。开放 kind 在这里救了场——**系统从不阻止我发明新类别**。

## 现场 5：数据清洗流水线（Orange 地盘）

我想把"读 sales.csv → 去重 → 补缺失值 → 归一化 → 建模"画出来。第一个块"读 sales.csv"的 out 槽该是什么类型？表。dataset。四件套里没有。number？不是。text？勉强——我填了 `"data/sales.csv"` 路径字符串。

于是一路传下去的"数据"全是路径字符串。荒谬吗？想了一会儿，不荒谬：**十万行数据本来就不该进图**，图传递的是"指代"，真数据住在文件系统里，将来 python 电池拿路径去读。

后知后觉（**G12，需要写成定位条款**）：大值（表/文件/图像/模型权重）永不入图，图只传指代（路径/名称/ref）。这个原则能自洽地解释四件套为什么够用，但**文档现在没写**，导致我每次遇到"表"都要重新纠结一遍 dtype。建议写进 00-charter 或 03 开篇。

另一个现场：管道中间我还没想好"补缺失值"用什么策略，那个块是空的——只有输入槽没有输出声明，悬空着。在 Orange 里这直接不可运行（widget 缺输入就灰掉）；在这里它安安静静待在图里，下游闭包标 undefined，其余支路照常。**部分求值活下来了，这是渐进形式化的核心红利。**

## 现场 6：开发一桌宴席菜单

生活场景。文本块写满想法：客人忌口、预算、备菜时间线。正式化几个关键量：`辣度预算`（number 槽 30）、`主菜成本`、`备菜总时长`。

菜单本质是**时序**的：腌 20 分钟 → 炸 → 调汁 → 合炒。我的边只能表达数据依赖，"先…然后…"表达不了。绕行：块内注释写步骤编号 + doodle 箭头串起时序（**G14，容忍**）。

汇合点来了：两条汁（糖醋汁、红油）进同一口锅。我试图把两条边接进"合炒"块的同一个 in 槽——**替换语义触发**：第二条边把第一条顶掉了！愣了两秒才想起 D-42：in 槽至多一条边。那"汇合"怎么办？答案是自己发明一个 `混合` 电池：两个 in 槽、一个 out 槽。合理——汇合本来就是一个操作，不该藏在边里。Orange/Blender 也是这么处理的。**存活，但文档欠一个"汇合模式"的配方说明**，新手第一次撞替换语义会懵。

客人突然说怕辣，辣度预算 30 → 15。改槽，下游"红油用量""警告标注"全部自动重算——爽。

然后我想**复制整套菜单**试一版不辣的变体：选中十几个块 → Ctrl+C → Ctrl+V……

**什么都没发生。**

翻了命令词汇表：没有 duplicate，没有 copy/paste。要让变体菜单存在，我得把每个块重新 promote、重新声明槽、重新连线，或者指望 agent 帮我重建。

后知后觉（**G1，重大缺口**）：复制粘贴——最古老的生产力操作——整个架构里不存在。这需要 `duplicateObjects(objIds)` 命令：复制块、内部边，以及组内跨组边是否跟随的语义。v1 必修。

## 现场 7：120 个模块的 UML 拓扑与重构

我在给我们学校的社团管理系统画软件拓扑。画到第 60 个模块电池时，画面已经是蜘蛛网。按空格——自动布局……**布局算法根本还没选型**（U-07），我甚至不确定 v1 实现的是力导向还是层次布局。对 120 节点的有向图，这个选择的差异是生死级的。

先不管，继续。我要把"支付"相关的 12 个模块收进一个 Subgraph：框选 → 打组为 Subgraph → 它缩成一个带端口的块。**收缩的那一刻很爽**。

然后我双击它想看内部。

**没有入口。** Subgraph 的"进入内部视图"交互压根没设计过。sealed 只是个标记位，双击的行为是空的。我翻了 04 全文——没有。

后知后觉（**G5，重大缺口**）：子图的 drill-in/drill-out 导航（双击进入、面包屑返回）是 Subgraph 可用性的前提，v1 哪怕做最简版（进入 = 画布切到该子图内容视图）也必须有。

硬着头皮用 violating 边先凑合内部连线。重构开始：把"风控模块"从支付子图挪到独立子图——框选 20 个块 → move → OK，命令在。但跨越子图边界的边瞬间变成 17 条红色虚线（violating）。正规做法是走子图对外槽——**然后我撞上了 U-18：对外槽的透传映射（外部槽 ↔ 内部哪个块的哪个槽）没有任何规格**。我没法把内部的一条边"引出"到子图端口上。

**卡死。** 最终我把这 17 条边全留成 violating，导出时报警就报警。Grasshopper 在这里会死（cluster 里没有任何自由注释的位置，每个节点还必须是合法电池）；Simulink 死在子系统必须是可运行模型。我活着，但子图这半条命是 U-18 欠的。

另外：120 个块里找"鉴权模块"靠肉眼扫——**没有搜索**（G11）。

## 现场 8：个人成本模型与单位的谎言

小生意算账：原料体积 × 密度 × 单价。我郑重其事地用了 quantity 槽：`体积 3.5 m³`、`密度 1000 kg/m³`。builtin 乘法跑起来——3.5 × 1000 = 3500。

单位呢？m³ × kg/m³ 应该得 kg，builtin 只算了数字。如果我把密度单位写错成 g/L，结果差一千倍，**系统一声不吭**。

后知后觉（**G7 第二撞**）：v1 的 quantity 实际上是"带单位注释的 number"，没有单位代数。这可以接受——Aspen 的物性引擎是几十人年的活——但要在文档里诚实写明：**v1 不防止单位错误，quantity 的单位是给人看的标签**。另外表达式求值的输入格式（builtin 怎么声明 "ρ*g*H*Q"？字符串表达式还是结构化？）至今无人定义。

这场景 Aspen 死在"必须收敛才能出数"，我死不掉因为我可以全手填——但单位安全的缺位是真实风险，至少 UI 应该在 quantity 槽上把单位字符串显示得足够显眼。

## 现场 9：三千字文献笔记的半年漂移

学期初我写了个 3000 字的文献综述文本块，从中 promote 了 8 个正式块（各论文的结论、三个待验证假设）。origin 回链当时很好用：点一下块，原文对应句子闪一下高亮。

半年后我重写了那篇笔记——结构全变，句子搬家。现在 8 个块里 6 个挂着 origin-lost 角标，黄澄澄一片。角标没有错（origin 只是软回链，设计上就不跟随），但**视觉噪声**是真实的，而且我其实希望其中 3 个块的 text 副本更新成我改后的表述——

没有这个命令。按 D-11，副本创建即脱钩，永不双向同步——这是对的，我不想回到锚定流沙。但一个**显式的、一次性的** `refreshFromOrigin(objId)`（用 origin 重新复制覆盖 text，需确认）完全符合哲学：不同步，但允许我主动"再抄一遍"。

后知后觉（**G8**）：缺 refreshFromOrigin 命令；角标需要"一键全部隐藏/忽略"的开关。

另一个撞点：3000 字的文本块，它的 rect 是我手动拉的固定框。文字写多了之后——溢出？块自动长高？**没定义**（G9）。我现在的块要么文字被裁掉，要么我手动拉高，排版全靠手感。文本块的高度策略（内容自适应 + 最小 rect）是每天都在流血的细节。

还有：想找"实验 B 的假设块"——120 个对象里靠肉眼（G11 再撞）。

## 现场 10：疲劳反馈环，以及"活"的缺席

我自己的状态管理：`疲劳` → `效率` → `完成度` → `压力` → 回到 `疲劳`。负反馈环，delay 边剪环——每条边的因果我在注释里写得清清楚楚。这个场景是 delay 边 + status 传播的主场，**结构性地成立**。

我想看它"转起来"：疲劳累积 → 效率滑坡 → 拖延 → 更疲劳的螺旋。手动按了五次"跑一步"，看着数值一帧一帧劣化——能看，但笨拙。真正的动态感要等 v2 的 tick 循环 + 历史快照（G6 第三撞）。

不过有一个意外的收获：我把"心情"做成了一个 text 槽（`心情:[烦躁]`），它作为 manual 输入参与"效率"电池的启发式注释推理——虽然 v1 算不了"烦躁让效率乘 0.7"这种语义，但这个**软变量能体面地存在于图里**，没有被类型系统拒之门外。Loopy 能做的定性循环，我们至少能画出来并留好未来求值的接口。

## 现场 11：Agent 一口气建了 30 块，然后我拆了 5 条边

我让 agent（假 agent，固定命令序列版）搭一维传热模型：它调用 createObject/declareSlot/connect 三十次，两秒出图。没有 origin（凭空创建合法，D-50），rect 是它自己排的——**全叠在画布中央一堆**，因为 agent 不懂布局美学。框选全部 → 空格 → 又是那个没选型的布局算法（U-07 第三撞）。

检查时发现 agent 接错了 5 条边。删除、重连。中途我还手改了两段注释文本。Ctrl+Z 撤销时，图操作和打字再次交替回退（G10 再撞）——而且 agent 的 30 个 Command 各占一格，我按 Z 按到手酸。**agent 批量命令需要一个"事务折叠"概念**（一次 agent 任务 = 一个可整体 undo 的宏命令），这之前没人提过——记入 G10 的延伸。

好的一面：agent 走的是和我完全相同的 Command Bus，所以它的错误可以被我像对待自己的错误一样撤销，schema 校验拦下了它一次 dtype 非法的 connect。**同一总线的设计在这里兑现了全部承诺。**

## 现场 12：我想把五段笔记码整齐——然后发现文本层是孤儿

收尾工作：黑板左边散落着 5 个文本块笔记，我想把它们整体挪到右下角码齐。

框选——**只圈住了正式块**。文本块对框选无反应。一个一个拖？拖了三个我停了：右键菜单没有"全选文本块"，没有批量移动文本层的任何入口。

后知后觉（**G2，重大缺口**）：双层分工（D-46）把框选划给了正式块层，文本层从此失去了所有批量操作。这与"文本是黑板的主体"自相矛盾——黑板上最多的东西反而最不被待见。修法应该很轻：框选默认双层通吃（文本块被框中后同样可批量移动/删除，只是不参与连线），或者 Alt+框选 = 仅文本层。**当时的仲裁方案只想到了"避免冲突"，没想到"文本层也需要被选择"。**

# 结论

## 一、活下来的机制（真金不怕火炼清单）

| 机制 | 经受的考验 | 现场 |

| 独立副本 + origin 软回链 | 半年笔记重写风暴没有伤到一个正式块 | 9 |
| manual 遮蔽规则 | 手填值接上真边自动让位、断边恢复，草稿↔正式过渡零摩擦 | 3, 2 |

## 三、为什么这 12 个场景里传统工具全都活不下来

| 工具 | 死因（在上述场景的映射） |
| --- | --- |
| **Grasshopper** | 每个节点必须是合法电池才能存在——现场 1/4/7 里我一半的块在创建时是"还没想清楚"的；cluster 内不允许自由注释，UML 场景直接不可能 |
| **Simulink** | 画图前必须定义全部信号维度/类型/求解器——现场 2/3 我连回流比和 Kp 都没想好；子系统必须是可运行模型，做不到"先画个框" |
| **n8n** | 节点 = 真实集成，不存在"某种过滤器，回头定"——现场 4 第一步就死 |
| **Aspen** | 物性方法 + 规格完备 + 收敛三座大山——现场 2 在"R 待定"处即死 |
| **Orange** | widget 固定且缺输入不可运行——现场 5 的空块策略与现场 1 的"人"类型双双判死 |

共同死因一句话：**它们都要求"先想清楚再进入系统"，而真实工作（尤其 MCM 这种地狱）是"边进入边想清楚"。** 这正是渐进形式化的生态位，压力测试确认这个生态位在机制上成立——代价是上面 G1–G11 的补课清单。

## 四、对文档体系的直接冲击（本文引出的待办）

1. G1/G2/G3/G5/G7/G9/G10 → 需要在 01 台账新增 D 编号（定方案后）或 U 编号（待定方案），并同步修改 02 命令词汇表、03 schema、04 交互。
2. G12/G13/单位安全 → 00-charter 与 03 的边界条款补写。
3. U-07（布局算法）在三个现场被撞——优先级应从"痒了再定"上调为 **v1 步骤 2 期间必须定**。
4. U-18（子图透传）被现场 7 证明无法拖到 v2，至少需要最小规格进 v1。
5. D-46（框选仅正式块层）需要按 G2 修订。
